# Adversarial Robustness of Abstract Visual Reasoning Models

White-box PGD (and C&W-style targeted) adversarial attacks on **PredRNet**
trained on **I-RAVEN**, plus two lightweight defenses (input preprocessing,
adversarial fine-tuning). See `coding_agent_prompt.md` for the full spec this
project implements.

## Status

This is a **code-complete scaffold**: every script below is implemented and
has been smoke-tested end-to-end (train -> attack -> analyze -> defend) on a
tiny synthetic dataset with random weights. What has **not** been run yet:

- Downloading/generating the real I-RAVEN dataset (~3.5 GB)
- Training PredRNet to convergence (paper reports ~60-75% test accuracy)
- The full attack/defense evaluation sweeps on real data

Do those on a machine with a working CUDA-enabled PyTorch build and enough
disk space; the commands below are exactly what to run.

## Setup

```bash
pip install -r requirements.txt
```

PredRNet is already cloned into `models/predrnet/` (from
https://github.com/ZjjConan/AVR-PredRNet). All code here imports from it via
`common/paths.py` rather than modifying it directly.

**GPU note:** this scaffold was built and smoke-tested in an environment
whose installed PyTorch build is CPU-only. If you have a CUDA GPU, install a
matching `torch`/`torchvision` build (see https://pytorch.org) before
training for real -- everything auto-detects CUDA via `common.utils.get_device`
and falls back to CPU otherwise.

## Step 1 -- Get the I-RAVEN dataset

I-RAVEN has no direct download; it's generated by the SRAN repo's Python
**2.7** generator. Read and run:

```bash
bash data/prepare_iraven.sh 10000   # 10,000 samples per config x 7 configs, ~3.5 GB
```

This creates a throwaway `conda` env (`iraven-gen`, Python 2.7), clones
https://github.com/husheng12345/SRAN into `data/_sran_src/`, and writes
`data/i-raven/<config_folder>/RAVEN_<k>_<split>.npz`, matching what
`common/dataset.py` (and PredRNet's own loader) expect.

## Step 2 -- Train PredRNet (Stage 1)

```bash
python train.py --data-dir data/i-raven --epochs 100 --batch-size 128 \
    --num-extra-stages 3 --block-drop 0.1 --classifier-drop 0.1
```

Logs per-epoch train loss / val accuracy to `logs/training_log.json`, prints
+ saves final per-config test accuracy to `logs/final_test_results.json`, and
saves the best checkpoint to `checkpoints/best_model.pth`. Expected clean
accuracy: ~60-75% overall (paper-reported range).

## Step 3 -- Run the PGD attack and measure ASR (Stage 2)

```bash
python attack/evaluate_attack.py \
    --checkpoint checkpoints/best_model.pth --data-dir data/i-raven \
    --epsilon 8 --steps 20 --num-samples 1000 \
    --epsilons 2,4,8,16 --steps-list 5,10,20,40 \
    --include-cw \
    --output results/
```

Produces:
- `results/attack_results.json` -- per-sample clean/adversarial predictions
- `results/attack_summary_table.csv` -- ASR by config x epsilon x num_steps
- `results/adversarial_examples/<config>/example_*.png` -- original vs.
  adversarial context images + amplified (x10) perturbation
- `results/cw_attack_results.json` -- C&W targeted-hijack results (with `--include-cw`)

Quick sanity checks for the individual attack classes:

```bash
python attack/pgd_attack.py --checkpoint checkpoints/best_model.pth --data-dir data/i-raven
python attack/cw_attack.py  --checkpoint checkpoints/best_model.pth --data-dir data/i-raven
```

## Step 4 -- Analyze why the attack works (Stage 3)

```bash
python attack/analysis.py \
    --checkpoint checkpoints/best_model.pth --data-dir data/i-raven \
    --attack-results results/attack_results.json --output results/analysis
```

Produces `results/analysis/per_config_breakdown.csv`, gradient-magnitude
saliency overlays (`saliency/*.png`), a t-SNE plot of PE embeddings
(`tsne_pe_features.png`), and `analysis_report.md` (rule-disruption is left
as a manual/qualitative section, per the spec).

## Step 5 -- Defenses (Stage 4)

Preprocessing defense (no training needed, just evaluate):

```bash
python defense/preprocessing_defense.py \
    --checkpoint checkpoints/best_model.pth --data-dir data/i-raven
```

Adversarial fine-tuning:

```bash
python defense/adversarial_training.py \
    --checkpoint checkpoints/best_model.pth --data-dir data/i-raven \
    --epochs 10 --epsilon 8 --steps 7
```

Compare both defenses (clean / after-attack / after-attack+defense, plus
preprocessing inference overhead):

```bash
python defense/evaluate_defense.py --defense both \
    --checkpoint checkpoints/best_model.pth \
    --adv-checkpoint checkpoints/adv_trained_model.pth \
    --data-dir data/i-raven \
    --output results/defense_comparison_table.csv
```

## Design notes

- **Pixel convention**: all attack/defense code operates on images scaled to
  `[0, 1]` (`common/dataset.py`); `common.model.RPMModel` rescales to the
  `[-1, 1]` range PredRNet's backbone expects internally, so `epsilon`/`alpha`
  budgets are always in clean `[0, 1]` units (e.g. `8/255`).
- **Threat model**: only the 8 context images are perturbed; the 8 answer
  candidates are always clean, per `coding_agent_prompt.md`.
- **PGD** (`attack/pgd_attack.py`): untargeted, maximizes cross-entropy
  against the true answer, standard sign-gradient ascent with random start
  and an L-infinity projection each step.
- **C&W** (`attack/cw_attack.py`): targeted at the candidate answer image
  with the largest pixel-L2 distance from the correct answer (the "worst
  distractor"), optimized in tanh space with an optional L-infinity cap.
- **Defense evaluation threat model**: the preprocessing defense assumes a
  non-adaptive attacker (PGD generated once against the undefended model,
  standard for non-differentiable input transforms like JPEG); the
  adversarial-training defense assumes a fully white-box attacker (PGD is
  regenerated directly against the fine-tuned weights), since those weights
  are the deployed model.
- Seeding: every script seeds `torch`/`numpy`/`random` via
  `common.utils.set_seed` (default 42).
